# 笙（しょう）シミュレータ 設計書

雅楽の管楽器「笙」をブラウザ上で再現するシミュレータの設計ドキュメント。
**画面構成 / 音響構成 / システム仕様** の3部で構成する。

- 対象プラットフォーム: **Webブラウザ**（Web Audio API + Web MIDI API）
- 音源方式: **物理・合成モデル**（フリーリード物理モデルを AudioWorklet で実装）
- 主目的: **17管の単音・自由演奏**（任意の和音を奏者が自由に構成できる）

---

## A. 設計判断ログ（枠組み・確定）

実現が難しい所・後戻りの高い所から先に確定した中核判断。詳細根拠は各章に展開する。

| ID | 判断 | 内容 | 状態 |
|---|---|---|---|
| D1 | **励起は共有息モデル** | 「17独立ボイス＋各envelope」を廃し、**1本の息（グローバル励起）→ ゲートされたリード群 → 合算**とする。実物の笙どおりで、実装も単純・正確 | 確定 |
| D2 | **既定は本格（息を入れて発音）** | 管の押下＝指孔を塞ぐ＝発音の選択（armのみ）。息圧（スライダ/キー/MIDIブレス）を与えて初めて鳴る。息の強弱が表現の中心 | 確定 |
| D3 | **タップは入力層で実装** | 「押せば鳴る」簡易モードはエンジンを二重化せず、押下時に既定息エンベロープを注入する**入力アダプタ**として上に乗せる | 確定 |
| D4 | **fallback音源は廃止** | AudioWorklet を必須前提とする（現行モダンブラウザは全対応）。非対応環境はメッセージ表示のみ。音色系統の二重化を避ける | 確定 |
| D5 | **DSPコアはWASM化可能な境界に** | まずJSのAudioWorkletで試作。計測でCPU不足なら**DSPコアのみWASMに差替え**できるよう、worklet境界を薄く保つ | 確定 |
| D6 | **M0スパイク先行** | 本実装(M1)前に音源スパイクで物理モデルの成立性とCPU予算を実証してから確定（§4.8） | 確定 |

### 技術リスク登録簿（要監視）

| リスク | 影響 | 緩和策 |
|---|---|---|
| **フリーリード物理モデルが笙らしく鳴らない/数値不安定** | 音色品質・プロジェクト成否 | M0で物理寄り(案A)と息駆動合成(案B)を並行試作し耳とCPUで採否決定。安定化のためオーバーサンプリング＋リミッタ |
| **17リード同時でCPU予算超過（特にモバイル）** | 音切れ・レイテンシ悪化 | 共有息で励起は1本に集約。JS計測→不足時WASM(D5)。係数事前計算・分岐/確保削減 |
| **入力→可聴レイテンシ > 30ms** | 演奏感の悪化 | `latencyHint:'interactive'`、最小バッファ、AudioWorklet内完結。M0で実測 |
| **調律値の正確性が不明** | 音高の正統性 | 調律表をデータ駆動(`tuning/*.json`)化し、校正は後フェーズに分離（設計リスクではない） |

## 0. 用語

| 用語 | 意味 |
|---|---|
| 管（かん）/ 竹 | 笙を構成する17本の竹管。各管にフリーリード（金属簧）が付く |
| 律名（りつめい） | 各管の固有名（千・十・下・乙…）。本書ではこれを管IDとして用いる |
| 合竹（あいたけ） | 複数管を同時に鳴らす伝統的なクラスター和音。標準で11種 |
| 手移り（てうつり） | 合竹から合竹へ運指を移す技法 |
| 無音管 | 簧を持たない（または塞がれた）管。「也（や）」「毛（もう）」の2本 |
| ブレス | 息（吹く／吸う）による励起。笙は吹いても吸っても発音する |

## 1. 楽器仕様（モデル化の前提）

### 1.1 構造
- 17本の竹管を匏（ほう＝頭）に環状に挿した構造。
- 各管の根元に**金属フリーリード（簧, した）**があり、息の往復（呼気・吸気の双方）で振動して発音する。
- 音高は主にリードの質量・剛性（調律蝋の量）で決まり、管の長さがその基音を共鳴で補強する。
- 各管の側面に**指孔**があり、孔を指で塞いだ管だけが発音する。
- 15管が発音し、2管（**也・毛**）は無音。

## 2. 画面構成

### 2.1 設計方針
- **単音・自由演奏が最優先**。17管それぞれを独立に押下／離鍵でき、任意の同時発音（マルチタッチ／複数キー）に対応する。
- 笙の実物に近い**正面ビュー（環状/扇状の竹配列）**を中心に据え、押した管が即座に視覚フィードバックする。
- ブレス（息）操作を1つの軸として常時露出させる。

### 2.2 レイアウト全体図

```
┌──────────────────────────────────────────────────────────┐
│  ヘッダー: ロゴ | 調律: 平調 ▾ | 基準A4: 442Hz | ⚙設定 │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                   ┌── 笙ビュー（中央）──┐                │
│                   │     扇状/環状に       │                │
│                   │   17本の竹を配置       │   ┌────────┐ │
│                   │  押下管=発光+音高表示   │   │プリセット│ │
│                   │   也・毛 は無音表示     │   │ 合竹一覧 │ │
│                   └──────────────────────┘   │(任意)   │ │
│                                              └────────┘ │
├──────────────────────────────────────────────────────────┤
│  ブレスバー ◀━━━━━●━━━━━▶ 吸 0 吹   | 持続/タッチ切替    │
├──────────────────────────────────────────────────────────┤
│ フッター: 入力デバイス[マウス/タッチ/PCキー/MIDI] | 録音● │
└──────────────────────────────────────────────────────────┘
```

### 2.3 主要コンポーネント

1. **笙ビュー（ShoView）**
   - 17本の竹を実物配列で描画（SVG）。各竹は `pipeId`（律名）を持つ。
   - 状態: `idle / pressed / sounding / disabled(無音管)`。押下中は発光＋律名・音名・周波数をツールチップ表示。
   - 入力: クリック／マルチタッチ／ドラッグでのグリッサンド的な連続押下。
   - 表示トグル: 律名のみ / 西洋音名 / 周波数 / 運指ヒント。

2. **ブレスコントロール（BreathControl）**
   - 息圧を -1.0（吸う最大）〜 +1.0（吹く最大）で表現。中央0は無音。
   - モード（既定＝本格モード, D2）:
     - **本格モード（既定）**: 管の押下は arm（無音）。スライダ／キー（例: スペース）／MIDIブレスで息圧を与えて初めて発音。息の強弱が表現の中心。
     - **タップモード**: 管を押すと既定息エンベロープを自動注入し即発音、離すと止む（鍵盤的な簡易操作）。エンジンは同一で、入力アダプタによる切替（D3）。
   - 入力ソース: スライダ、PCキー、MIDIブレスコントローラ（CC2）、ゲームパッドのトリガ。

3. **設定パネル（SettingsPanel）**
   - 調律（基準ピッチ、調律表選択、微分音オフセット/セント）。
   - 音源パラメータ（後述: リード剛性、息ノイズ量、立ち上がり時間、共鳴Q、リバーブ量）。
   - 入力マッピング（PCキー⇔管、MIDIノート⇔管）。
   - アクセシビリティ（コントラスト、ラベル常時表示、キーのみ操作）。

4. **プリセット/合竹パネル（PresetPanel・任意表示）**
   - 標準合竹11種をボタン化。押すと該当管セットを一括点灯・発音。
   - 自由演奏の補助であり、デフォルトは折りたたみ。

5. **録音・書き出し（Recorder）**
   - 演奏（管ON/OFF＋息圧）のイベント列を記録し、再生／WAV書き出し（OfflineAudioContext）／MIDI書き出し。

### 2.4 入力マッピング（既定案）
- **PCキーボード**: 下段・上段キーを発音15管へ割当（例: `Z X C V B N M , . / A S D E F G H` …管数に合わせ可変）。`Space`=息ON（持続）。
- **マウス/タッチ**: 竹を直接押下。マルチタッチで和音。
- **MIDI**: ノートオン/オフ→管（音高一致 or 任意マッピング）、CC2/CC11→息圧。
- 無音管（也・毛）は押下しても発音せず、視覚的に「無音」を明示。

### 2.5 視覚フィードバックとレスポンス
- 押下→発音までの体感遅延を最小化（目標: 入力から発音まで < 30ms）。
- 発音中の竹は明度＋色相で強度（息圧）を表現。
- 同音管（例: D5が複数）には微小なデチューン/位相差を与え、実楽器のうなりを再現。

## 3. 音響構成

### 3.1 方針
笙は**フリーリード**楽器であり、(a) 息の往復で発音、(b) 立ち上がりに息ノイズと微小ピッチ揺れ、(c) 同時発音時の自然なうなり、が音色の核。これらをパラメトリックに制御するため**フリーリード物理モデルを AudioWorklet（カスタムDSP）で実装**する。

**核となる構造は共有息モデル（D1）**：独立ボイスの集合ではなく、**1本の息（グローバル励起）→ 指孔ゲートで選択されたリード群 → 合算**。鳴っている全管が同じ息圧で一緒に膨らみ・減衰する（実物どおり／合竹が溶け合う音響的理由）。fallback合成は持たない（D4）。

### 3.2 信号フロー（共有息 → リードバンク）

```
[Breath 入力 (スライダ/キー/MIDI CC2)]
        │  -1.0(吸)〜0(無音)〜+1.0(吹)
        ▼
┌───────────────────────────┐
│ Global Excitation          │  息は全リードで共有（1本）
│ ・息圧→流量  ・吸/吹を整流  │
│ ・閾値未満は無音            │
│ ・息ノイズ(チャフ)生成      │
└──────────────┬─────────────┘
               │ 共有励起信号 e(t)
       ┌───────┼───────┬───────────────┐
       ▼       ▼       ▼               ▼   （×15 発音管）
  ┌─────────┐┌─────────┐         ┌─────────┐
  │ Reed[行] ││ Reed[一] │  …      │ Reed[五] │  各リード:
  │ gate=指孔││ gate=指孔│         │ gate=指孔│  ・指孔ゲート(arm)
  │ f0=調律  ││ f0=調律  │         │ f0=調律  │  ・非線形バネ質量(自励)
  │ +共鳴/Q  ││ +共鳴/Q  │         │ +共鳴/Q  │  ・±数centデチューン
  └────┬────┘└────┬────┘         └────┬────┘  ・無音管(也/毛)は不在
       └──────────┴──── 合算 ──────────┘
                        ▼
        ┌────────────────────────────────┐
        │ Master Bus                      │
        │ 息ノイズ床 → 軽リバーブ(空間)   │
        │ → ソフトリミッタ → 出力          │
        └────────────────────────────────┘
```

> 「ボイス割当」は不要。発音管は最大15で固定なので、リードはバンクとして常駐し**指孔ゲート（arm/disarm）**で開閉する。押下＝arm（無音）、息圧>閾値で発音（D2）。「タップモード」は押下時に既定息エンベロープを注入する入力アダプタ（D3）で、この信号フローは変えない。

### 3.3 フリーリード物理モデル（コア）
- **励起**: 息圧 `p`（-1..+1）を流量へ変換。吸気/呼気は流量方向が反転するが、フリーリードは双方向で振動するため整流して励起に用いる。`|p|` が閾値未満なら無音、閾値超過で自励発振を開始。
- **リード振動子**: 1自由度の非線形振動子（質量・バネ・減衰）。固有周波数 `f0` は管の調律値（`tuning/*.json`）で決定。息圧に応じた微小なピッチ依存（プレッシャー・ベンド）と立ち上がりの揺らぎを付与。
- **管共鳴**: バンドパス（または短いデジタル導波路）で `f0` とその倍音を補強し、笙特有の澄んだ倍音構成を作る。共鳴Qを設定で可変。
- **アタック/リリース**: 息圧の立ち上がり/立ち下がりに連動。アタックに息ノイズ（チャフ）を短時間ミックス。
- **うなり**: 同音高の管・複数同時発音時に各リードへ ±数セントのランダム・デチューンを与え自然なうなりを生成。

実装メモ: AudioWorkletProcessor 内でサンプル毎にリード状態を更新。1ボイス=軽量DSP、17ボイスでもモバイルWeb想定で動作する負荷に収める（係数の事前計算・分岐削減）。

### 3.4 DSP実装方針（JS→WASM 差替え可能に, D5）
AudioWorklet は必須前提とし、fallback合成は持たない（D4）。DSPコアはまず **JS の AudioWorkletProcessor** で実装して高速に反復する。M0計測でCPUが不足する場合に備え、**リードバンクのDSPコアのみ WASM（C/Rust→wasm）に差し替えられる**よう worklet 境界を薄く保つ（worklet＝I/Oとパラメータ授受、コア＝純粋なサンプル処理関数）。

音源アルゴリズムはM0スパイクで2案を比較し採否を決める（§4.8 M0）:
- **案A（物理寄り）**: 非線形リード（質量・バネ・減衰）＋モーダル/BPF共鳴。本格だが重く数値安定性にリスク。
- **案B（息駆動合成）**: 息でエンベロープ/倍音を駆動する加算・減算合成。物理ではないが軽量・安定・制御容易。

### 3.5 音響パラメータ（設定で露出）
| パラメータ | 範囲/例 | 効果 |
|---|---|---|
| reedStiffness | 0.5–2.0 | 立ち上がりの硬さ・倍音量 |
| breathNoise | 0–1 | 息ノイズ床の量 |
| attackTime | 5–80ms | 発音の立ち上がり |
| resonanceQ | 5–40 | 管共鳴の鋭さ |
| detuneSpread | 0–8 cent | 同時発音のうなり量 |
| reverbMix | 0–0.4 | 空間（雅楽堂内）残響 |
| basePitch | 430–445Hz | 基準A4 |

### 3.6 レイテンシ/ポリフォニー要件
- ポリフォニー: 最大15リード同時発音（全発音管）。共有息のため励起は1本、リードはバンク常駐でボイス割当不要。
- 目標往復レイテンシ: 入力→可聴 < 30ms（`AudioContext.latencyHint='interactive'`、バッファ最小化）。
- サンプルレート: コンテキスト既定（44.1/48kHz）に追従。

## 4. システム仕様

### 4.1 アーキテクチャ概要

```
┌───────────────────────── UI 層 (View) ─────────────────────────┐
│ ShoView | BreathControl | SettingsPanel | PresetPanel | Recorder│
└───────────────┬───────────────────────────────┬────────────────┘
                │ イベント(管ON/OFF, 息圧, 設定)   │ 状態購読
                ▼                                ▼
┌───────────────────────── アプリ層 (Core) ──────────────────────┐
│ InstrumentStore(状態) | InputRouter | TuningService | PresetSvc │
│ ・押下管集合/息圧/モード ・キー/MIDI/タッチ統合 ・調律解決      │
└───────────────┬───────────────────────────────┬────────────────┘
                │ ボイス制御(noteOn/Off, breath)  │ パラメータ
                ▼                                ▼
┌───────────────────────── 音響層 (Audio) ───────────────────────┐
│ AudioEngine → AudioWorklet(ReedVoice×17) → Mixer → Master(FX)   │
│ フォールバック: WebAudioGraphEngine                              │
└─────────────────────────────────────────────────────────────────┘
        ▲ Web MIDI API   ▲ Web Audio API   ▲ Pointer/Touch/Keyboard
```

### 4.2 技術スタック（提案）
- 言語: **TypeScript**
- UI: 軽量フレームワーク（React もしくは Web Components）+ **SVG** で笙ビュー描画
- 音響: **Web Audio API** + **AudioWorklet**（DSP, 必須前提・fallbackなし D4）。CPU不足時は DSPコアを **WASM**(C/Rust) に差替え（D5）
- 入力: **Web MIDI API**、Pointer Events（マルチタッチ）、Keyboard Events
- 書き出し: OfflineAudioContext（WAV）、簡易MIDIライタ
- ビルド: Vite。テスト: Vitest（ロジック）＋手動音響確認
- 配布: 静的ホスティング（SPA、インストール不要）。PWA化でオフライン対応可

|---|---|
| `InstrumentStore` | 押下管集合・息圧・演奏モードの単一状態管理。UIと音響に通知 |
| `InputRouter` | マウス/タッチ/PCキー/MIDI を共通の `pipeOn/Off`・`breath` に正規化 |
| `TuningService` | 調律表ロード、基準ピッチ＋centsから各管 `f0(Hz)` を算出 |
| `PresetService` | 合竹プリセットの読込・適用（一括ON） |
| `AudioEngine` | AudioContext/Worklet 初期化、共有息の送出、指孔ゲート(arm/disarm)、パラメータ反映 |
| `ReedBank`(Worklet) | 共有励起＋15リードのバンクDSP（指孔ゲート・固有周波数・共鳴）。コアはWASM差替え可(D5) |
| `Recorder` | イベント記録・再生・WAV/MIDI書き出し |
| `SettingsStore` | 音響/入力/表示設定の永続化（localStorage） |

### 4.5 状態と同期
- 単一の `InstrumentStore` を真実源とし、UIは購読、`AudioEngine` はコマンド受信。
- 無音管（`sounding:false`）は `pipeOn` を受けても音響側で発音せず、UIは「無音」状態を表示。
- 息圧0かつ全管OFFで全ボイス無音。息圧>閾値かつ管ONで発音。

### 4.6 非機能要件
- **レイテンシ**: 入力→発音 < 30ms（4.5/3.6参照）。
- **対応ブラウザ**: Chromium系/Firefox/Safari の AudioWorklet・Pointer 対応版。MIDIは未対応ブラウザではUIで明示し無効化。
- **モバイル**: タッチ操作・縦横レイアウト対応。自動再生制約のためユーザー操作で AudioContext を resume。
- **アクセシビリティ**: キーボードのみで全管演奏可。ラベル/音名の常時表示オプション、コントラスト確保。
- **パフォーマンス**: 17ボイス同時でモバイル中位機でも音切れしない負荷（DSP最適化、GC回避）。
- **国際化**: 表示は日本語既定、ラベル（律名/西洋音名）切替。

### 4.8 開発フェーズ（マイルストーン）
0. **M0 音源スパイク（リスク先行検証）**: リード1〜3本＋共有息1本の最小AudioWorkletを作成。案A(物理寄り)と案B(息駆動合成)を耳とCPUで比較。15本スケール時の1レンダーquantum当たりCPUと入力→可聴レイテンシを実測し、(a)音色採用案、(b)JSで足りるか/WASM必須か、(c)レイテンシ<30ms到達可否を確定。**これが緑になってからM1へ**。
1. **M1 発音基盤**: AudioEngine + ReedBank(採用音源)で15管を共有息で発音、PCキー/クリック対応。
2. **M2 笙ビュー**: SVGで17管描画、押下フィードバック、無音管表示、息圧スライダ。
3. **M3 物理モデル**: ReedBank(Worklet)実装、息双方向・うなり・息ノイズ、パラメータ設定。必要ならDSPコアをWASM化(D5)。
4. **M4 入力拡張**: マルチタッチ、Web MIDI、ブレスコントローラ。
5. **M5 調律/プリセット**: 調律表校正、合竹プリセット、設定永続化。
6. **M6 録音/書き出し**: イベント記録・再生・WAV/MIDI出力、PWA配布。
